## Implemented server contract

The API now serves `/.well-known/assetlinks.json` from `ANDROID_APP_LINK_SHA256_CERT_FINGERPRINTS`. It accepts comma-separated SHA-256 certificate fingerprints, uppercases and deduplicates them, rejects malformed entries and emits the fixed package `com.afterlifearchive.medmanager` with relation `delegate_permission/common.handle_all_urls`.

Missing or entirely invalid configuration returns HTTP 503 with `Cache-Control: no-store`; it never publishes an empty or guessed trust association. Valid output is JSON with a five-minute public cache. Integration tests cover fail-closed behavior, validation/normalization/deduplication and the complete response contract.

## C95 release gates

- `./gradlew verifyProductionAppLinks` requires the exact final `https://www.okusuri-mimamori.com/.well-known/assetlinks.json` URL with no redirects, HTTP 200, JSON content, five-minute cache, one exact package/relation statement and the complete independently supplied Play app-signing certificate set.
- `ANDROID_SERIAL=... ./gradlew verifyPlayInstalledAppLinks` first requires that production gate, then uses package-manager state on an API-31+ authorized physical device. It accepts only a package installed by `com.android.vending`, signed by the same Play app-signing certificate set, with only `www.okusuri-mimamori.com` in `verified` state.
- Pure contracts accept single-certificate and intentional-transition web surfaces plus single/transition installed states, and reject 30 HTTP/JSON/cache/trust/signer/installer/domain-state failures. Hosted CI runs these pure contracts without external network or a fabricated production certificate.

The Release manifest previously declared both apex and `www` in one verified filter. Android requires a redirect-free Digital Asset Links file on every declared host, while the apex file redirects and all production API/email redirect configuration is canonical `www`. C95 therefore removes apex from the manifest/artifact policy; the internal callback parser remains defensive, but Release no longer promises direct verification for a host that cannot satisfy the domain contract.

## Production completion steps

1. Enable Play App Signing and obtain the **App signing key certificate SHA-256** from Play Console. Do not add the upload certificate to the production association.
2. Put the same value in local/CI-only `PLAY_APP_SIGNING_CERT_SHA256_FINGERPRINTS` and production Vercel `ANDROID_APP_LINK_SHA256_CERT_FINGERPRINTS`; deploy the exact merged API commit.
3. Run `./gradlew verifyProductionAppLinks`; do not substitute curl output or a synthetic fingerprint.
4. Install the Play-delivered build and run `ANDROID_SERIAL=... ./gradlew verifyPlayInstalledAppLinks`.
5. Open both production `/auth/...` paths on the canonical `www` host externally and confirm direct Android routing, browser fallback when absent, and no custom-scheme dependency.

The production signing certificate and deploy authority are not available locally, so this remains `PARTIAL` rather than `VERIFIED`.
